# 마디 Windows판

macOS판과 같은 기능을 Windows에서 내는 두 번째 앱입니다(사용자 — "윈도우 버전 만들어줘 기능 동일하고", 고른 구조: C안,
번역은 일단 뺌). **지금 3단계까지입니다** — 열고 고치고 저장하고, 라이브 프리뷰 · 찾기 · 목차, 바깥에서 바뀐 파일 다시 읽기 ·
따라 보기, `.txt` · `.log`(1단계), 표 · 할 일 상자 · 알림 · Mermaid · KaTeX · 그림 · 메타데이터 카드, 테마 여덟 · 다크 · 글꼴 · 글자 크기 ·
줄 사이 · 글 폭, 빠른 열기 · 명령 팔레트 · 최근 문서(2단계), 코드 블록의 문법 색, PDF 내보내기 · 프린트, `madi://` 링크 · 한 번만 켜기,
새 판 확인, LLM 키, 설치 파일(사용자별 · 파일 연결 · 서명 없음)(3단계), Microsoft Store용 MSIX, 그리고 모양을 다시 — 메뉴 막대 · 상태
줄 대신 제목 막대, 글을 고르면 뜨는 서식 막대, 둥근 코드 블록 · 표 · 알림(사용자 — "디자인이 별로인데… loomm.ai/mark 이거 느낌").

## 구조 — 왜 이렇게 했나

| 자리 | 하는 일 | 쓰는 것 |
|---|---|---|
| `editor/` | 편집기와 문서 로직 — 인코딩 · 줄 끝, 라이브 프리뷰 · 블록 그림, 찾기, 목차, 고친 상태 · 자동 저장, 바깥 변경 들이기, 테마 · 설정 값, 고르는 칸(거르기) | TypeScript, [CodeMirror 6](https://codemirror.net/), esbuild, Mermaid · KaTeX(macOS판과 같은 파일) |
| `Madi.Windows/` | 창 · 메뉴 · 열기 · 저장 창, 파일 읽고 쓰기, 파일 지켜보기, 닫을 때 묻기, 설정 · 최근 문서 저장, 빠른 열기의 후보, 로컬 그림 읽기, 글꼴 목록 | C# · WPF(.NET 10), [WebView2](https://learn.microsoft.com/microsoft-edge/webview2/) |
| `Madi.Windows.Tests/` | 껍데기의 파일 로직 시험(xunit v3, Windows에서만) | |
| `installer/` · `msix/` | 설치 파일(Inno Setup) · Microsoft Store용 MSIX 꾸러미 — `msix/README.md`에 올리는 순서 | Inno Setup 6 · Windows SDK |

- macOS판의 라이브 프리뷰는 `NSLayoutManager`가 마크다운 표식의 글리프를 지우는 데 기대고, Windows에는 그 대응물이 없다.
  CodeMirror 6의 장식(decoration)으로 표식을 숨기는 것은 이미 검증된 길이다(Obsidian의 라이브 프리뷰가 이 방식이다).
- 한글 조합(IME)은 Edge(WebView2)가 맡는다. 다이어그램 · 수식(Mermaid · KaTeX)은 macOS판도 웹 엔진으로 그리므로 같은 화면에서 된다.
- 껍데기는 얇게 둔다 — 로직은 `editor/src/core/`에 두어 이 Mac에서도 Node로 시험한다(`npm test`). C#은 Windows에서만 빌드된다.
- 대가: macOS판의 Swift Core를 TypeScript로 한 벌 더 갖는다. 기능을 더하면 두 번 만든다.

### 껍데기 ↔ 편집기

웹 메시지만 주고받는다(호스트 객체를 열지 않는다). 편집기는 exe 옆의 `editor\` 폴더를 `https://app.madi/`로 열고, 그 밖의 주소로는
가지 않는다. 브라우저 단축키(F5 새로 고침 · Ctrl+P …)는 껐다 — 새로 고침은 고친 글을 버린다. 바이트는 base64로 오간다.

| 보내는 쪽 | 메시지 | |
|---|---|---|
| 껍데기 → 편집기 | `open` | 파일의 **바이트**. 글로 읽는 일(인코딩 · BOM · 줄 끝)은 편집기가 한다 |
| 껍데기 → 편집기 | `appended` · `replaced` | 지켜보는 파일의 끝에 붙은 바이트 · 다르게 바뀐 파일 전체 |
| 껍데기 → 편집기 | `saved` · `saveFailed` · `saveCancelled` · `run` | 저장의 결과, 메뉴에서 고른 명령 |
| 편집기 → 껍데기 | `ready` · `opened` · `state` | 떴다 · 읽은 꼴 · 문서 상태(이름 · 고침 · 부딪침 · 보기) — 제목 줄과 메뉴 체크가 따른다 |
| 편집기 → 껍데기 | `save` · `saveAs` · `reload` · `command` · `openUrl` · `drop` | 쓸 바이트, 다시 읽기, 새 창 · 열기 · 닫기, 링크, 끌어다 놓은 파일 |
| 양쪽 | `settings` | 설정(편집기가 정한 값). 어느 창에서 바꾸든 껍데기가 `%APPDATA%\Madi\settings.json`에 쓰고 열린 창 모두에 돌려준다. 첫 화면은 페이지를 띄우기 전에 넣어 둔 값으로(밝게 그렸다가 바뀌지 않게) |
| 편집기 → 껍데기 → 편집기 | `listFiles` → `files` · `listFonts` → `fonts` · `loadImage` → `image` | 묻고 답하기(`id`로 짝). 빠른 열기의 후보, 이 PC의 글꼴 이름, 로컬 그림의 `data:` 주소 |
| 편집기 → 껍데기 | `openPath` | 빠른 열기에서 고른 파일 |
| 껍데기 → 편집기 → 껍데기 | `output` begin → `outputReady` → (PDF) → `output` end | PDF 내보내기 — 편집기가 흰 종이 · 문서 전체로 그린 뒤 껍데기가 쓴다 |
| 껍데기 → 편집기 | `compose` · `run`(`goToLine` · `search` · `appendText` · `caretEnd`) | `madi://` 링크의 새 문서 · 줄로 가기 · 찾기 · 끝에 더하기 |

## 쓰는 법

| 단축키 | 하는 일 |
|---|---|
| `Ctrl+N` · `Ctrl+O` | 새로 만들기(새 창) · 열기(여러 개 고를 수 있다) |
| `Ctrl+S` · `Ctrl+Shift+S` | 저장 · 다른 이름으로 저장 |
| `Ctrl+W` | 닫기 |
| `Ctrl+F` · `F3` · `Shift+F3` | 찾기 · 다음 · 이전(찾기 칸에서 `Enter` · `Shift+Enter`) |
| `Ctrl+E` | 원본 보기 |
| `Ctrl+Alt+L` | 따라 보기 |
| `Ctrl+Shift+O` | 목차 |
| `Ctrl+P` | 프린트하기(macOS판 ⌘P — 2단계에는 빠른 열기였다) |
| `Ctrl+Alt+O` | 빠른 열기 — 열린 문서 · 최근 문서 · 지금 문서의 폴더(macOS판 ⌥⌘O) |
| `Ctrl+Shift+P` | 명령 팔레트 — 메뉴의 명령과 설정(테마 · 모양 · 글꼴 · 줄 사이 · 글 폭 …) |
| `F10` | 메뉴(제목 막대의 `…`) — 파일 · 편집 · 서식 · 보기 · 도구 · 도움말 |
| `Ctrl+B` · `Ctrl+I` · `Ctrl+Shift+X` · `Ctrl+Shift+C` · `Ctrl+K` | 굵게 · 기울임 · 취소선 · 인라인 코드 · 링크 — 다시 누르면 풀린다(macOS판 서식 메뉴의 ⌘ 자리) |
| `Ctrl+1`~`Ctrl+6` · `Ctrl+Alt+0` | 제목 1~6 · 본문 |
| `Ctrl+Shift+8` · `Ctrl+Shift+7` · `Ctrl+Shift+9` · `Ctrl+Alt+Q` · `Ctrl+Alt+C` | 글머리 · 번호 · 할 일 목록 · 인용 · 코드 블록 |
| `Ctrl+=` · `Ctrl+-` · `Ctrl+0` | 글자 크게 · 작게 · 기본 크기(10~28, 기본 15) |
| `Ctrl+클릭` | 링크를 기본 브라우저로(`http` · `https` · `mailto`만) — 표 칸 · 메타데이터 카드의 링크도 |

- **열기**: 파일을 창에 끌어다 놓거나 exe 아이콘에 놓아도 연다. 이미 연 파일이면 그 창이 앞으로 온다. 빈 창(저장한 적 없고 고친 것도
  없음)에는 그 자리에, 아니면 새 창에.
- **저장**: 이름 있는 문서는 고친 뒤 1.5초 쉬면 저장하고, 닫을 때도 묻지 않고 저장한다 — macOS판의 자동 저장과 같다. 저장한 적 없는
  문서는 닫을 때 묻는다. 같은 폴더의 임시 파일에 다 쓴 뒤 바꿔 넣는다(쓰다 멈춰도 반쯤 쓴 파일이 남지 않는다). 연 꼴을 지킨다 —
  UTF-8 · BOM · UTF-16 · CRLF 그대로. EUC-KR · windows-1252는 UTF-8로 쓴다(macOS판과 같다). 새 문서는 UTF-8 · LF.
- **라이브 프리뷰**: 캐럿이 없는 줄은 표식(`#` · `**` · `*` · `~~` · `` ` `` · `[…](주소)` · `> `)을 숨기고 꾸민다. 글머리 `-`는
  ● ○ ■(깊이마다), `---`는 선. 캐럿이 있는 줄은 원문 그대로 — macOS판과 같은 약속이다. 제목 크기는 macOS판의 배율.
- **원본 보기**: 쓴 그대로, 고정폭(IBM Plex Mono). `.txt` · `.log`는 이것으로 연다 — 창 폭을 다 쓰고, 마크다운 문법을 칠하지 않고, 목차가
  없다. 끄면 마크다운으로 그린다.
- **따라 보기**: 고칠 수 없게 하고 끝을 따라간다. `.log`는 이것으로 연다. 위를 읽는 동안 줄이 붙으면 그 자리에 두고 `새 줄 N개 ↓`.
  창 크기가 바뀌어도 끝에 남는다.
- **바깥에서 바뀐 파일**: 고친 것이 없으면 묻지 않고 들인다 — 끝에 붙은 것은 붙은 바이트만(덜 쓴 한 글자는 다음 조각과 합쳐),
  다르게 바뀌면 다른 가운데만 갈아 끼운다(캐럿 · 읽던 자리가 남는다). 고친 것이 있으면 섞지 않고 위에 띠를 띄운다 —
  `다시 읽기`(여기 것을 버림) · `내 것 지키기`(여기 것을 씀). 고를 때까지 자동 저장을 멈춘다. 그때 닫으면 묻는다.
- **제목 막대**(맨 위 한 줄 — 메뉴 막대와 아래 상태 줄을 대신한다): 왼쪽에 목차, 문서 이름(●는 저장하지 않은 고침), 알아야 할 것만 작은
  표시로(따라 보기 · UTF-8이 아닌 인코딩 · CR 줄 끝), 오른쪽에 찾기 · 원본 보기 · 열기 · 메뉴(`…`)와 창 단추. 색은 테마를 따른다 —
  글과 한 판이다. 메뉴는 맨 위에 자주 쓰는 것(macOS판의 버거 메뉴와 같은 차례), 아래에 전의 메뉴 막대 전체. 저장 · 설정 같은 알림은 아래
  가운데에 잠깐 뜬다(자동 저장은 알리지 않는다). 인코딩 · 줄 끝 · 줄 수는 `보기 ▸ 문서 정보`.
- **서식 막대**: 글을 고르면 그 위에 뜬다(macOS판과 같은 자리 · 규칙) — 제목 ▾ · 굵게 · 기울임 · 취소선 · 인라인 코드 · 링크 · 목록 셋 ·
  인용 · 코드 블록 · 표 · 구분선. 눌러도 선택이 남아 이어서 누를 수 있다. 마우스로 고르는 동안 · 한글 조합 중 · 따라 보기에서는 숨는다.
  서식 규칙은 macOS판 `MarkdownFormatting`을 그대로 옮겼다(`src/core/formatting.ts` — 시험도 옮겼다).
- **붙여 넣기의 줄 끝**: 붙여 넣거나 끌어다 놓은 글의 줄 끝을 문서의 줄 끝으로 맞춘다 — Windows의 클립보드 글은 CRLF라 LF 문서에 `\r`이
  섞였다(CRLF 문서에는 LF가). 링크의 `append` · `new`도 같다.
- **블록 그림**: 맨 위 단계의 표 · ```` ```mermaid ```` · ```` ```math ```` (· `katex`) · `$$ … $$`(여러 줄 · 한 줄) · 한 줄짜리
  그림(`![설명](자리)`) · 맨 위의 `---` 메타데이터는 그림으로 바꿔 보인다. 캐럿(선택)이 그 블록에 닿으면 원문 — 누르면 원문이 된다.
  닫는 펜스가 없거나 빈 줄로 끊긴 `$$`는 쓰는 중으로 보고 그리지 않는다. 틀린 원문은 그 자리에 Mermaid · KaTeX의 오류 문장.
  Mermaid(5.5MB) · KaTeX는 그런 블록이 처음 보일 때 싣는다. Mermaid는 `securityLevel: "strict"`, KaTeX는 `trust: false`(macOS판과 같다).
- **그림**: 상대 경로는 문서 폴더가 기준이다(저장한 적 없는 문서는 풀 수 없다). 껍데기가 그림 확장자의 파일만 25MB까지 읽는다.
  원격 그림은 **https만**, `보기 ▸ 원격 그림 받기`를 켰을 때만 — 문서를 연 것만으로 바깥에 요청이 나가지 않는다.
- **메타데이터 카드**: 키 · 값, 목록은 칩(여덟 개 넘으면 `외 N개`). 머리 줄을 누르면 접고 편다. `보기 ▸ 문서 메타데이터 접어 두기`면
  접힌 채로 연다. 읽기만 한다 — 고치려면 카드를 눌러 원문으로. 원문은 YAML 그대로 한 장의 고정폭 상자다(마크다운으로 꾸미지 않는다 —
  닫는 `---`가 가로줄이나 제목 밑줄이 되지 않게). 파일을 열면 캐럿은 앞머리 다음 줄이라 카드로 보인다. 목차는 앞머리를 건너뛴다.
- **할 일 · 알림**: `- [ ]`는 상자(누르면 파일의 글자 하나가 `x`로 바뀐다, 따라 보기에서는 누르지 않는다), 끝낸 일은 흐리게 긋는다.
  `> [!NOTE]` · `TIP` · `IMPORTANT` · `WARNING` · `CAUTION`은 그 색의 상자와 제목.
- **테마 · 설정**: `보기 ▸ 테마` 여덟(기본 · Notion · Confluence · GitHub · Obsidian · 종이 · Solarized · 고대비 — macOS판의 색),
  `모양`(시스템 따라 · 밝게 · 어둡게), `글꼴`(이 PC의 글꼴에서 고른다, 기본은 앱에 든 Pretendard · IBM Plex Mono), `줄 사이`, `글 폭`
  (본문 크기의 42 · 56 · 76배, 창 폭 전체). 모든 창이 함께 바뀌고 다음에 켜도 남는다. 브라우저의 확대(Ctrl+휠)는 껐다.
- **코드 블록**: 펜스의 언어(macOS판과 같은 이름 · 별명 — Swift · JavaScript · TypeScript · Python · 셸 · JSON · Rust · Go · YAML · CSS ·
  HTML · SQL)로 문법 색을 칠한다. 색은 테마의 것. 언어 꾸러미는 그 블록이 처음 보일 때 싣는다(`dist/chunks/`). 모르는 이름은 칠하지 않는다.
  마우스를 블록 위에 두면 오른쪽 위에 `복사` 단추가 뜬다(macOS판과 같은 규칙 — `core/codecopy.ts`). 펜스는 빼고, 목록 안의 블록은 펜스의
  들여쓰기만큼 빼고 베낀다. 클립보드에는 Windows의 CRLF로 넣는다. 블록의 위가 굴려져 가려지면 보이는 칸의 맨 위에 붙는다. 인용 안의 블록 ·
  그림이 된 다이어그램 · 수식에는 없다. 클립보드는 편집기(Chromium)의 것을 먼저 쓰고, 막히면 껍데기가 Win32로 바로 넣는다
  (`TextClipboard.cs` — WPF의 `Clipboard`는 클립보드를 지켜보는 프로그램 앞에서 실패했다).
- **블록 위젯에는 바깥 margin을 쓰지 않는다**: CodeMirror가 위젯 높이를 테두리 상자로 재서 margin을 세지 못한다 — 위젯마다 높이 지도가
  어긋나 그 아래의 클릭 · 굴리기 · 복사 단추 자리가 밀렸다. 사이는 `.md-block`의 padding, 테두리 · 바탕은 안쪽 상자에.
- **PDF · 프린트**(파일 ▸ PDF 내보내기… · 프린트하기…): macOS판과 같은 약속 — 고른 테마 · 다크와 상관없이 흰 종이에 기본 색, 캐럿
  줄의 표식도 숨기고, 메타데이터는 내지 않는다, 글은 여백 안을 다 쓴다. 용지(시스템 기본 · A4 · Letter) · 방향 · 여백(24 · 48 · 84pt)은
  파일 ▸ 프린트 설정에서 — 둘이 같은 값을 쓴다. 프린트하기는 Edge의 프린트 창이 뜬다(거기서 프린터 · PDF로 저장을 고른다).
- **`madi://` 링크**: `open?path=…[&line=N][&search=…]` · `new?text=…[&title=…][&path=…]` · `append?path=…&text=…` — macOS판과 같은
  명령이다. `path`는 드라이브부터 적은 절대 경로(`C:\…` · `C:/…`), `~\…`, `file:///C:/…`만, 마크다운 · 글 · 로그 파일만 받는다. `append`는
  더할 글을 보이고 묻는다(기본은 `아니요`). `new?path=`는 있는 파일을 덮지 않고 폴더를 만들지 않는다. **네트워크 경로(`\\서버\…`)는 받지
  않는다** — Windows는 그 경로를 여는 순간 그 서버에 로그인 정보(NTLM)를 보낸다. 셸에서: `start "" "madi://open?path=C:/메모/a.md&line=3"`.
- **한 번만 켜기**: 마디가 켜져 있으면 두 번째로 켠 마디(탐색기에서 파일을 두 번 누름 · 링크)는 받은 것을 넘기고 곧 끝난다. 받은 것 없이
  다시 켜면 새 창. 사용자마다 따로고, 같은 사용자의 프로그램만 넘길 수 있다(파이프가 그 사용자만 받는다).
- **새 판 확인**(도움말 ▸ 업데이트 확인… · 하루 한 번 새 판 확인, 기본 켜짐 — macOS판과 같다): 켤 때와 켜 둔 동안 하루 한 번 GitHub에
  판을 묻는다(GET 하나). 그 판에 Windows판 설치 파일(`Madi-<판>-windows-x64-setup.exe`)이 있고 판이 높을 때만 알린다. **저절로 바꿔
  넣지는 않는다** — 서명하지 않은 판이라 받은 파일이 진짜인지 가릴 길이 없다(macOS판도 서명하지 않은 빌드는 받는 페이지만 연다).
- **LLM 키**(도구 ▸ LLM 키…): macOS판과 같은 다섯 서비스(Anthropic · OpenAI · Gemini · Groq · Bedrock)의 키를 Windows 자격 증명 관리자에
  두고, 그 서비스에 모델 목록을 물어 확인한다. **문서는 보내지 않는다** — macOS판에도 교정 자체는 아직 없다(보낼지는 결정이 필요한 일).
- **빠른 열기**: 지금 문서의 폴더는 숨은 것 · `node_modules` · `DerivedData` · `Pods` · `vendor` · `*.assets`를 건너뛰고 파일 2000개 ·
  항목 20,000개에서 멈춘다(macOS판과 같다). 이름에 맞는 것이 위치에만 맞는 것보다 앞이다. 최근 문서는 `파일 ▸ 최근 문서`에도(스무 개).

### macOS판과 다른 것

| | macOS판 | Windows판 | 까닭 |
|---|---|---|---|
| UTF-8이 아닌 파일 | UTF-16 → Latin-1 | BOM 있는 UTF-16 → EUC-KR → windows-1252 | 한국어 Windows의 옛 파일은 CP949 |
| UTF-16 파일 저장 | UTF-8로 | UTF-16 그대로 | Windows의 메모장 · 프로그램이 UTF-16을 쓴다 — 바이트를 지킨다 |
| 찾기 | 도구 막대의 칸, 대소문자 · 분음부호 무시 | CodeMirror의 찾기 칸 — 대소문자 · 정규식 · 낱말 단위를 고르고, 바꾸기도 된다 | 분음부호 무시는 없다(다음 단계 후보) |
| 창 부제 | `원본 보기` · `따라 보기` | 제목 막대의 단추(원본 보기)와 작은 표시(따라 보기) | Windows의 창에는 부제가 없다 |
| 메뉴 | 화면 맨 위의 메뉴 막대 + 도구 막대의 버거 메뉴 | 제목 막대의 `…`(F10) 하나 | 창마다 메뉴 막대를 두면 글 위에 줄이 하나 더 생긴다 |
| 메타데이터 | 편집기 밖, 위의 카드(글에서 떼어 낸다) | 글 안의 카드 — 누르면 그 자리가 원문 | 한 편집기 안에서 블록과 같은 약속(캐럿이 닿으면 원문) |
| 다이어그램 · 수식 | 숨은 웹뷰에서 그려 PDF로 받아 붙인다 | 편집기 페이지 안에서 바로 그린다(SVG · HTML) | 편집기가 이미 웹 엔진이다 |
| 명령 팔레트 | 메뉴 바를 훑는다 | 편집기의 명령 표(`core/catalog.ts`) — 메뉴도 같은 이름을 부른다 | 메뉴(WPF)와 편집기가 다른 프로세스다 |
| 코드 블록 색 | 직접 쓴 한 번 훑기(`CodeHighlighter`) | CodeMirror의 언어 문법(Swift · 셸은 CodeMirror 5 모드) | 이름 · 별명은 같고, TypeScript는 따로 칠한다 |
| 링크의 경로 | `/…` · `~/…` · `file://…` | 드라이브부터(`C:\…`) · `~\…` · `file:///C:/…`, 네트워크 경로는 받지 않는다 | NTLM — 위 |
| 업데이트 | 받아 서명을 보고 끌 때 바꿔 넣는다 | 알리고 받는 페이지만 | 서명(Authenticode)이 없다 |
| 설치 | DMG · Homebrew | 설치 파일(사용자별) · 압축 파일 · Microsoft Store(MSIX — Store가 서명) | winget · 설치 파일의 서명은 판을 낼 때 |

## 빌드 · 실행(Windows)

```powershell
cd windows\editor
npm ci
npm test
npm run build            # dist\ — 껍데기가 이것을 exe 옆 editor\로 옮긴다
cd ..
dotnet run --project Madi.Windows.Tests -c Release    # 껍데기 시험
dotnet run --project Madi.Windows -- 문서.md
```

필요한 것: Node 24 이상, .NET 10 SDK, WebView2 런타임(Windows 11에는 들어 있다). 편집기만 볼 때는 이 Mac에서도 `npm run build` 뒤
`dist/`를 `python3 -m http.server --bind 127.0.0.1 --directory dist`로 열면 된다(호스트가 없으면 빈 문서).

## CI — `.github/workflows/windows.yml`

`windows/**` 가지에 올리거나 `windows/`를 고친 PR에서 `windows-latest`가 편집기 시험 · 형 검사 · 묶기, 껍데기 시험 · 빌드(x64, .NET 포함),
확인 실행(`Madi.exe --smoke <폴더>`)을 돈다. 확인 실행은 창 하나로 실제 길(파일 읽기 · 지켜보기 · 저장)을 지나며 본다:

1. 시험 문서 다섯(CP949 · UTF-16LE BOM · 섞인 줄 끝 · UTF-8 BOM CRLF · UTF-8 LF)을 열어 편집기를 지나도 바이트가 그대로인지(SHA-256)
2. 고쳐서 저장하면 BOM · CRLF가 남는지, 내가 쓴 것을 바깥 변경으로 읽지 않는지
3. 로그가 따라 보기로 열리고 붙는 줄을 따라가는지, 한 글자를 둘로 나눠 써도 한 번만 들어오는지
4. 고친 것이 있는데 바깥에서 바뀌면 띠로 묻고 자동 저장을 멈추는지, `내 것 지키기`가 여기 것을 쓰는지
5. 라이브 프리뷰 · 목차를 켠 화면(`editor.png`), 앱에 든 글꼴이 편집기 글에 **실제로 쓰이는지**(계산된 CSS — 0단계의 처음 빌드는
   `style.css`의 규칙이 CodeMirror 기본 테마에 밀려 쓰이지 않았다. 그래서 편집기의 글꼴 · 꾸밈은 `src/editor/setup.ts`의 테마에 둔다)
6. 블록 그림 — 메타데이터 · 표 · Mermaid · 수식 둘 · 그림이 모두 그려졌는지(오류 없이), 할 일 상자를 누르면 파일에서 그 글자 하나만
   바뀌는지(`blocks.png` · `blocks-end.png`)
7. 모양 — 글을 고르면 서식 막대가 뜨고 `굵게`가 고른 글만 감싸는지, 제목 막대가 빈 자리 · 단추 · 위 끝을 창 끌기(2) · 누르기(1) · 크기
   바꾸기(12)로 답하는지, 최대화해도 창 단추가 작업 영역 안이고 막대 아래쪽까지 창을 끄는지, EUC-KR 문서가 제목 옆에 표시를 다는지, 메뉴(…)가
   뜨는지(`design.png` · `menu.png` — 창째 찍는다, 제목 막대까지)
8. 명령 팔레트가 `githb`로 `GitHub` 테마를, 빠른 열기가 최근 문서에서 `showcase.md`를 찾는지(`palette.png` · `quickopen.png`)
9. 한 번만 켜기 · `madi://` — 같은 exe를 두 번째로 켜면 넘기고 끝나는지(끝 코드 0), 켜진 마디가 연 창 · `open`의 줄 · `append`(묻고,
   목록에 잇고, 자동 저장) · `new`(제목 · 글, `path`면 새 파일, 있는 파일은 덮지 않음) · 네트워크 경로 거절
10. 설정 — GitHub 테마 · 어둡게 · 글자 크게가 편집기의 계산된 색 · 크기에 쓰이고 `settings.json`에 남는지(`blocks-dark.png`).
   확인 실행은 사용자의 설정 · 최근 문서를 건드리지 않는다(그 폴더 안의 `settings\`, 한 번만 켜기도 이름을 따로 — `smoke`)
11. PDF — 다크에서 내보내도 흰 종이 · 문서 전체 · 메타데이터 없음(`output.png`), PDF가 여러 쪽(보이는 화면만이 아니라), 끝나면 다크로
    돌아오는지(`export.pdf`, 마지막 화면). 5에서 코드 블록의 문법 색도 본다(Swift의 `let`이 본문과 다른 색). 코드 복사 단추도 5에서 —
    블록에 마우스를 올리면 뜨고, 누르면 **실제 클립보드**에 펜스를 뺀 두 줄이 CRLF로 들어가고 `복사됨`으로 바뀌는지(`codecopy.png`)

확인 실행 뒤에 설치 파일을 만들고(Inno Setup) 조용히 깔아 파일 · `madi://` · 연결 프로그램 · 기본 앱 목록이 놓였는지 보고, 지워서 다
없어지는지 본다. 이어서 Store용 MSIX를 만들고(`msix/build.ps1`), 시험 인증서로 서명한 사본을 깔아 **꾸러미 안에서 확인 실행을 한 번 더**
돌리고(터미널 별칭 `madi.exe`로 켜서 — 결과의 `packageFamilyName`으로 꾸러미 안이었는지 본다), Windows App Certification Kit의 결과를 적은
뒤 지운다.

`editor.png` · `blocks*.png` · `design*.png` · `menu.png` · `palette.png` · `quickopen.png` · `output.png` · `screen.png` · `export.pdf` · `result.json` · `settings\*.json`을
남긴다. 받을 것: `Madi-windows-x64-setup`(설치 파일), `Madi-windows-x64-msix`(Store에 올릴 서명 없는 `.msix` · 꾸러미 안의 확인 실행 ·
WACK 보고서), `Madi-windows-x64`(풀어서 `Madi.exe`), `smoke`.

서명하지 않은 exe라 처음 열면 SmartScreen이 막는다 — `추가 정보` ▸ `실행`. 받은 zip은 속성에서 `차단 해제`를 먼저 누르면 편하다.

### 설치 파일 — `installer/Madi.iss`

사용자별(관리자 권한 없이 `%LOCALAPPDATA%\Programs\Madi`), 시작 메뉴에 마디, 마크다운 · 글 · 로그 확장자의 "연결 프로그램"에 마디,
`madi://`, 설정 ▸ 기본 앱의 목록에 마디(`RegisteredApplications`). 기본 앱을 스스로 바꾸지는 않는다 — Windows가 막고, 사람이 고를 일이다
(도구 ▸ 기본 앱 설정 열기). 지우면 이 항목들을 지운다(설정 · 최근 문서 `%APPDATA%\Madi`는 남긴다). 판 번호는 `Madi.Windows.csproj`의
`Version`. 아직 하지 않은 것: **서명**(Authenticode 인증서가 필요하다 — 사람이 정할 일), **winget**(판을 낸 뒤 microsoft/winget-pkgs에 PR).
서명 없이 SmartScreen 경고를 없애는 길은 Microsoft Store다(`msix/` — Store가 서명한다).
