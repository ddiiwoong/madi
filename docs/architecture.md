# 구조

마디를 고치려는 사람이 **깨뜨리면 안 되는 것**을 먼저 적습니다. 기능별 동작은
[기능 안내](features.md)에 있습니다.

## 층

```
Sources/Madi/
  Core/        순수 로직. Foundation만. AppKit·CoreGraphics 없음
  Editor/      라이브 프리뷰 편집기 (NSTextView + TextKit)
  Panels/      사이드바 · 카드 · 시트 · 설정
  Services/    Apple 번역, 압축 해제 — 플랫폼 API에 붙는 것
  App/         NSDocument · 윈도우 컨트롤러 · 메뉴 · main
Tests/MadiTests/   Core 파일을 직접 컴파일해 돈다 (앱을 띄우지 않음)
```

위에서 아래로만 의존합니다. `Core`는 자기 위의 어느 층도 모릅니다.

## 불변식 1 — `Core`는 Foundation만 쓴다

`make core-only`가 `Core`의 파일들만 따로 타입 체크합니다. 여기에 AppKit 타입이 들어오면
실패합니다.

이 검사는 장식이 아닙니다. 한 번 조용히 깨진 적이 있습니다 — `ImageReference`가 `CGSize`를
쓰고 있었는데, 앱 빌드에서는 같은 모듈의 AppKit이 CoreGraphics를 끌어와 **아무 오류도 나지
않았습니다.** `Core`만 따로 컴파일해서야 드러났습니다.

검사가 무엇을 잡고 무엇을 못 잡는지도 재 봤고 Makefile에 적어 두었습니다:

- 잡는다: `NSColor`, `NSView`, `CGSize.zero` 같은 멤버 접근
- **못 잡는다**: 맨 `CGFloat` — macOS의 Foundation이 이미 재노출합니다
- **못 잡는다**: `Compression` 프레임워크 — macOS SDK에 있으니 통과합니다. 하지만 Windows에는
  없습니다. 그래서 EPUB의 압축 해제는 `Core`가 **주입받고**(`Services/Inflate.swift`가
  구현) 구조 읽기만 `Core`에 있습니다. 검사가 못 잡는 것은 설계로 막아야 합니다.

처음 이 검사를 `swiftc -parse`로 썼더니 AppKit 타입을 넣어도 **통과했습니다**(구문만 보고
타입을 풀지 않습니다). 실패하지 못하는 검사는 없는 것보다 나쁩니다 — `-typecheck`여야 합니다.

## 불변식 2 — 저장되는 것은 사용자가 쓴 그대로다

문서 모델을 거쳐 다시 직렬화하지 않습니다. 그래서 **열고 저장만 해도 파일이 달라지는 일이
없습니다.** 이 불변식에 걸리는 기능이 셋 있고, 모두 "보여 주기는 바꾸되 글자는 건드리지
않는" 쪽으로 풀었습니다.

| 기능 | 흔한 방법 | 왜 쓸 수 없었나 | 마디의 방법 |
|---|---|---|---|
| 마커 숨김 | 마커를 지운다 | 원문이 사라진다 | 글리프 폭을 0으로 |
| 표 열 맞추기 | 칸에 공백을 끼운다 | 저장 시 원문이 바뀐다 | 글자 간격(`.kern`) |
| 인라인 이미지 | `U+FFFC`를 끼워 넣는다 | 원문에 글자가 추가된다 | `minimumLineHeight`로 자리만 비우고 직접 그린다 |

front matter도 같은 이유로 **원문 블록을 바이트 그대로** 들고 있다가 저장할 때 다시 붙입니다.

### 마커 숨김의 실제 방법

`NSLayoutManagerDelegate`에서 해당 문자를 **제어문자로 보고하고**
`shouldUse:forControlCharacterAt:`에서 `.zeroAdvancement`를 돌려줍니다.

처음에는 더 직관적으로 보이는 `.null` 글리프 속성을 썼는데 **같은 런의 뒤쪽 문자 매핑이
깨졌습니다** — `# 마디 에디터`의 `# `를 숨기면 "에디터"가 화면에서 사라졌습니다(텍스트
저장소에는 그대로 있었습니다). 렌더링을 직접 캡처해 보고 나서야 발견한 문제입니다.

### 인라인 이미지가 `NSTextAttachment`가 아닌 이유

실측으로 막혔습니다. 보통 글자에 `.attachment` 속성만 주면 줄 높이가 **18pt에서 꼼짝도
하지 않고**(`U+FFFC`를 끼워 넣은 쪽은 80pt), 글자를 끼워 넣으면 원문이 달라집니다.
`minimumLineHeight`는 글자를 하나도 더하지 않고 같은 80pt를 확보합니다.

## 스타일링 패스

`Editor/MarkdownStyler.swift`가 한 번의 다시 칠하기에서 차례로 돕니다.

1. 줄 스캔 (`Core/MarkdownSyntax.swift`) — 블록 종류와 코드 펜스 상태
2. 블록 스타일 — 제목·인용·목록·코드블록
3. 인라인 스타일 — 굵게·기울임·코드·링크 (표 행 안에서도 동작합니다)
4. 구문 강조 (`Core/CodeHighlighter.swift`) — 코드 본문 줄을 **블록 단위로** 넘깁니다.
   줄 하나씩 넘기면 `/* */`가 어디서 끝나는지 알 수 없습니다.
5. 표 열 맞추기 (`Core/MarkdownTable.swift`)
6. 이미지 자리 비우기

더럽혀진 범위가 블록의 일부뿐이어도 블록은 통째로 훑고 **쓰는 것만** 그 범위로 좁힙니다 —
줄 스캔이 이미 같은 이유로 늘 전체를 보고, 비용은 쓰기와 레이아웃 무효화에 있습니다.

**오프셋은 전부 UTF-16입니다.** `NSTextStorage`에 그대로 넘기기 때문이고, 그래서 주석이나
문자열에 한글·이모지가 있어도 뒤의 구간이 밀리지 않습니다.

**글꼴을 가정하지 않습니다.** 열 맞추기는 그 줄의 실제 속성에서 글꼴을 읽어 폭을 잽니다 —
본문 글꼴로 재면서 표는 고정폭으로 그리면 구분 행이 어긋납니다(그 버그가 있었습니다).

## 테스트가 앱을 띄우지 않는 이유

처음에는 앱 호스트 방식(`TEST_HOST`)으로 만들었는데 러너가 연결 전에 **355초를 멈췄습니다**
("The test runner hung before establishing connection"). 앱 자체는 정상 실행되므로 호스팅
문제였고, `Core`가 Foundation만 쓰니 호스트를 뗄 수 있었습니다 — 365개가 몇 초 안에 끝납니다.

그래서 테스트 타깃은 `Tests/MadiTests`와 `Sources/Madi/Core`를 **둘 다 소스로 컴파일**하고
`@testable import`를 쓰지 않습니다. `Core`에 파일을 더하면 자동으로 들어갑니다.

`Editor`도 함께 컴파일합니다 — 블록 편집기의 되돌리기·블록 넘는 선택·한글 조합 보호는
응답자 연쇄와 실제 `NSTextView`를 지나야 참임을 알 수 있고, 순수 모델 테스트만으로는
배선이 끊긴 것을 못 잡습니다(⌘A가 모델에는 실리는데 뷰에 싣는 순간 한 블록으로 줄어드는
결함을 UI로 더듬다 놓쳤습니다). 같은 이유로 `Panels/SettingsPanel.swift`도 넣습니다:
이 환경에서는 패널에 좌표 클릭이 닿지 않아(다섯 번 시도) 설정 컨트롤이 저장소까지
닿는지를 UI로 확인할 길이 없었습니다. 테스트가 창을 화면 밖에 만들고 컨트롤의
target-action을 AppKit과 같은 방식으로 쏩니다.

## 창이 쪼그라드는 함정

`contentViewController`를 할당하면 AppKit이 창을 **콘텐츠의 fitting size로 줄입니다.**
생성 시 `contentRect`만 주면 520x380 조각이 됩니다. `preferredContentSize`로 선언해야
합니다.

## 손대기 전에

```sh
make test        # 테스트 365개 — 가장 빠른 신호
make core-only   # Core가 아직 Foundation만 쓰는지
make build       # 앱 빌드
make universal   # arm64 + x86_64, lipo로 검사까지
```

UI를 바꿨으면 **실제로 띄워 눈으로 보십시오.** 이 저장소의 버그 중 테스트가 전부 통과하는
상태에서 화면만 틀렸던 것이 여럿 있습니다 — 사라진 "에디터" 글자, 창 오른쪽 절반에만 붙은
카드, 신호등 버튼과 겹친 사이드바 탭, 표 행에 아예 걸리지 않던 인라인 스타일.
