# md

의존성 0개 · 빌드 0단계 마크다운 에디터. 문서 내 검색은 **Mark.app 0.7.1을 역공학해서
그 동작을 그대로 옮긴 것**이고, 다른 점은 아래에 전부 적어 두었습니다.

```
npm test          # node:test, 24개
npm run serve     # http://127.0.0.1:4173 (루프백 전용)
```

`index.html`을 파일로 바로 열어도 동작하지만, ES 모듈이라 `file://`에서는 CORS로 막히는
브라우저가 있습니다. `npm run serve`를 쓰는 편이 안전합니다.

## 쓰는 법

| 키 | 동작 |
|---|---|
| `⌘F` | 검색창 열기 — 문서 안의 모든 일치를 호박색으로 칠함 |
| `Enter` / `Shift+Enter` | 다음 / 이전 일치로 이동 (**Mark에는 없는 기능**, 아래 참고) |
| `Esc` | 질의 비우고 검색창 닫기 |
| `⌘A` (검색창 안) | 질의 전체 선택 |
| `⌘E` | 분할 → 소스 → 미리보기 순환 |
| `⌘O` / `⌘S` | 열기 / 저장 |

입력 내용은 `localStorage`에 자동 보관됩니다. 파일 열기·저장은 File System Access API를
쓰고(Chrome·Edge), 없는 브라우저에서는 업로드 input과 내려받기로 대체됩니다.

## 검색이 어떻게 동작하는가 — 그리고 그 근거

이 검색은 상용 마크다운 에디터 **Mark.app 0.7.1**의 검색 **동작을 관찰해** 같은 규칙으로
구현한 것입니다. 그 앱의 코드를 가져오거나 옮긴 것이 아닙니다 — 아래 표는 밖에서 보이는
행동이고, 각 행은 같은 입력을 넣었을 때 같은 결과가 나오는지로 확인했습니다.

| 관찰된 규칙 | 어떻게 확인했는가 | 이 저장소 |
|---|---|---|
| 단순 부분문자열 — 정규식·퍼지 없음 | `a.*b` 같은 질의가 문자 그대로만 찾힌다 | `findMatches()` |
| 대소문자 무시, 토글 없음 | `ABC`와 `abc`가 같은 결과, 구분 옵션이 UI에 없다 | `findMatches()` |
| 일치 구간이 겹치지 않음 | `aaaa`에서 `aa`를 찾으면 2곳 | `findMatches()` |
| 질의의 앞뒤 공백은 무시 | ` 검색 `과 `검색`이 같은 결과 | `normalizeQuery()` |
| 코드블록·인라인코드는 칠하지 않음 | 코드 안의 일치만 있을 때 아무것도 칠해지지 않는다 | `highlight.js`의 `CODE_TAGS` |
| 입력에 디바운스가 있고, 큰 문서에서 더 길어진다 | 타자 중 강조가 한 박자 늦게 붙는다 | `debounceFor()` |
| 아주 큰 문서에서 한 글자 질의는 무시된다 | 큰 문서에서 한 글자를 넣어도 아무것도 칠해지지 않는다 | `shouldSearch()` |
| DOM을 바꾸지 않고 칠한다 | 강조된 글을 복사하면 표시가 따라오지 않는다 | CSS Custom Highlight API |
| 소스 패널은 미리보기와 다른 경로로 칠한다 | 같은 질의에 두 패널의 결과가 다르다(코드 제외 여부) | `segmentByMatches()` |

임계값(디바운스 80ms / 180ms, 큰 문서 18만 자, 한 글자 포기 25만 자)은 이 저장소가 고른
값이고 `src/search.js` 맨 위에 상수로 모여 있습니다. 강조색과 검색창이 열리는 방식도
비슷한 느낌을 목표로 **다시 고른 것**입니다 — 호박색 계열 배경에 폭 0에서 펼쳐지는
입력칸입니다. 단축키는 `⌘F`가 검색, `⌘⇧F`가 파일 브라우저로 같습니다.

### Mark와 일부러 다르게 한 것

1. **일치 이동과 개수 표시.** Mark에는 다음/이전 버튼도 개수 표시도 없습니다 — "현재
   문서의 모든 일치를 칠해 주는 필터"가 그쪽의 설계 의도로 보입니다. 다만 단독 에디터에서는
   일치가 화면 밖에 있으면 찾았는지조차 알 수 없어서 `Enter`/`Shift+Enter` 이동과
   `n / 총계` 표시를 더했습니다. 끄고 싶으면 `src/app.js`의 `Enter` 분기와 `#match-count`만
   지우면 됩니다.
2. **길이가 바뀌는 locale 소문자화 보정.** 터키어 `İ`처럼 소문자화하면 길이가 늘어나는
   입력에서는 그 뒤 인덱스가 모두 밀려 엉뚱한 글자를 칠하게 됩니다. `findMatches()`는
   길이가 달라지면 대소문자 구분 스캔으로 물러섭니다.
3. **일치가 코드 안에만 있을 때.** 미리보기는 코드를 건너뛰므로 개수가 0이 됩니다. 소스
   패널에는 노랗게 보이는데 "일치 없음"이라고 쓰면 거짓이라, 이 경우
   `코드 안에서만 일치 (n)`으로 표시합니다.

## 구조

```
index.html          화면 구조
src/search.js       검색 코어 — 순수 함수, DOM 의존 없음 (이식한 알고리즘)
src/highlight.js    미리보기 강조 — CSS Custom Highlight API, 코드 제외
src/markdown.js     의존성 없는 마크다운 렌더러 + 목차 추출
src/app.js          배선 — 패널, 단축키, 파일 입출력, 자동 보관
src/styles.css      테마 (라이트/다크 자동), 검색 강조색
test/               node:test 24개
```

`src/search.js`는 브라우저 API를 쓰지 않습니다. 그래서 테스트가 jsdom 없이 돌고, 소스
패널과 미리보기가 같은 판정 함수를 공유합니다.

## 보안상 정한 것

마크다운 렌더러는 **입력의 모든 문자를 먼저 HTML 이스케이프**하고, 원문 HTML을 그대로
통과시키지 않습니다. 그래서 별도 sanitizer가 필요 없습니다. 링크·이미지 URL은
`http`/`https`/`mailto`/상대경로만 허용하므로 `javascript:`·`data:`는 `href`에 닿지
않습니다. 두 규칙 모두 `test/markdown.test.js`에 테스트가 있습니다.

`npm run serve`는 `127.0.0.1`에만 바인딩합니다. 인증이 없는 정적 서버이므로 외부
인터페이스에 열지 마십시오.

## 알려진 한계

- 미리보기 강조는 CSS Custom Highlight API를 씁니다(Chrome 105+, Safari 17.2+,
  Firefox 140+). 없는 브라우저에서는 미리보기 강조만 꺼지고 소스 패널 강조는 동작하며,
  상태줄에 그 사실을 알립니다.
- 렌더러는 CommonMark 전체가 아닙니다. 참조 링크, 각주, 느슨한/엄격한 목록 구분,
  설정식(setext) 제목은 없습니다. 필요해지면 `src/markdown.js`에 넣으면 됩니다.
- 소스 패널은 textarea 위에 강조 레이어를 겹치는 방식이라, 두 요소의 font·padding·
  line-height가 어긋나면 강조가 글자에서 밀립니다. `src/styles.css`의
  `.source, .source-highlight` 공유 블록을 함께 고치십시오.
